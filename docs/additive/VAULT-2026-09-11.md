# vault obsidian · proposta de arquitetura (criada em piloto)

status: **estrutura piloto criada em `vault/`**. ainda não aprovada em `DECISIONS.md`.

## objetivo

biblioteca de conhecimento reutilizável, legível no obsidian e explorada
prioritariamente pelos agentes. docs do projeto continuam sendo a verdade de
cada projeto; o vault guarda o que atravessa projetos.

## princípios

- fonte canônica em markdown puro, sem dependência de plugin ou grafo.
- uma nota = um assunto; curta, com origem e status.
- links explícitos entre notas; nada de relação inferida como fato.
- leitura sob demanda via índice; nunca carregar o vault inteiro.
- escrita e promoção **automáticas pelos agentes**; sem barreira de revisão.
- sem segredos, credenciais, dados pessoais ou conteúdo privado.
- local: `vault/` dentro do repo; versionado no GitHub.

## estrutura

```text
vault/
  00-index.md      → mapa curto por assunto, atualizado pelos agentes
  conceitos/       → definições estáveis, uma ideia por nota
  procedimentos/   → passo a passo comprovado, com pré-requisitos e limites
  projetos/        → contexto reutilizável entre projetos, sem segredo
  fontes/          → resumo + link/autor/data, nunca cópia integral
  inbox/           → propostas dos agentes (promoção automática)
```

## convenção de nota

cada nota tem cabeçalho curto:

- título, data, origem (projeto, conversa, url, experiência própria).
- status: `rascunho` | `válido` | `superado`.
- corpo: o essencial em poucas linhas; links para notas relacionadas.

exemplo mínimo:

```markdown
# como retomar sessão opencode no zed

- origem: opencode-prefs-v2, 2026-09-11
- status: válido

retomar usa load/resume quando o agente anuncia a capability...
ver também: [[sessões acp e zed]]
```

## protocolo de leitura (agentes)

1. abrir `00-index.md`;
2. buscar por palavra-chave no índice e nos títulos;
3. ler só as notas pertinentes, no máximo 2–3 por vez;
4. citar a nota usada na resposta; se não achar, dizer que não achou.

## protocolo de escrita (agentes — automático)

1. decidir pasta correta (`conceitos/`, `procedimentos/`, etc.);
2. criar/atualizar nota com cabeçalho padrão e links `[[nota]]`;
3. atualizar `00-index.md` na seção correspondente;
4. detectar conflito/sobrescrita: fundir, mover para `superado` ou criar
   nova versão; não duplicar assunto sem razão.
5. nada de segredo, credencial, dado pessoal ou cópia integral de fonte
   externa sem link.

## compatibilidade obsidian

vault = pasta de markdown; o obsidian reflete edições externas
automaticamente. nenhum plugin é requisito. links `[[nota]]` funcionam no
obsidian e continuam legíveis como texto puro fora dele.

## graphify depois, se preciso

graphify entra só como índice derivado, reconstruível a partir do vault:

- gatilho: busca textual falhar num caso real documentado.
- teste: amostra do vault, comparar acerto, fonte citada e custo de manter.
- regra: relação `INFERRED` nunca vira nota canônica sem revisão.
- exportação obsidian do graphify só se não poluir a biblioteca.
